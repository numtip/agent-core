## Shipped today (VERIFIED)

### Rotation tooling — PR #34

`ops/rotate-project-tokens.py` rewritten. Before: fleet-wide only, no backup, a failed restart
reported as success, no post-rotation check. After:

- `--only <ids>` narrows the blast radius; fleet-wide stays the default so no onboarded project is
  dropped and existing runbooks keep their contract.
- Encrypted streaming backup (`age`, else `gpg`); **no plaintext fallback**. The payload goes from
  the open handle into the encryptor's stdin and only ciphertext reaches disk.
- Atomic replace re-asserts mode 600, fsyncs the directory, writes LF endings.
- A failed restart (or an unrunnable `systemctl`) is a reported failure, exit 2, with recovery
  guidance — never a traceback, never followed by a smoke test.
- `--base-url` smoke (auth-only by default), `--rollback`, `--restart-only`.

### Credential handoff — PR #35

`ops/handoff-project-token.py`. The payload lands in a **0600 temp file in the destination
directory**, its mode and sha256 are verified **before** the rename, and only then is it renamed
into place. A pre-rename failure therefore leaves an existing credential exactly as it was, and
the `EXIT` trap removes the temp on every failure path.

Rotation smoke became zero-cost: `{}` is rejected with `400 INVALID_REQUEST` *after*
authentication and *before* any provider call or audit row. An HTML response from the edge is
classified `EDGE` with its own exit code, so a Cloudflare problem is never misread as a bad token.
A production rotation without `--backup-recipient` is refused.

### Closed incident — unauthorized credential overwrite (VERIFIED)

An unauthorized `handoff-project-token.py --replace --apply` overwrote the VPS190 credential with
synthetic data. The credential was restored and its fingerprint verified. PR #36 prevents the
recurrence: overwriting now needs a separate acknowledgement (`--confirm-replace`, or
`HANDOFF_CONFIRM_REPLACE` set to the **exact** destination path — the env var carries the path so
an inherited variable cannot authorise a different destination).

Also recorded in PR #36: **piping to `head` is not a dry run.** `... --apply | head -1` still
writes. Closing the pipe truncates the report but does not undo a delivery, and can hide that the
write already happened, because the success line prints *after* the rename. A closed pipe now
exits 6 with an explicit stderr warning; Ctrl-C exits 130 with the same warning.

## Backups — age identity provisioned (VERIFIED, local only)

`age` v1.3.2 installed via winget from the verified publisher, and a production identity generated
after its directory was ACL-hardened first. Local workspace: `G:\ProjectAI\agent-core-local`.
**This workspace is deliberately not published**; nothing from it is committed here.

Findings worth not repeating:

- **`age-keygen`'s "world-readable" warning is meaningless on Windows.** It warns unconditionally,
  even for a file whose ACL has no broad ACE. Mechanism: Go's `os.FileMode.Perm()` returns `0666`
  for any writable file on Windows (it maps only the read-only attribute and cannot see NTFS ACLs),
  so age's `perm & 0077 != 0` test is always true. The ACL check is the authoritative control on
  Windows; on POSIX the warning still means a real exposure. The first generation attempt
  self-deleted the key over this (fail-closed and correct, but permanently blocking until fixed).
- Ordering is what prevents a world-readable interval: **harden the directory first, generate
  second**, so the new file inherits the private ACE at creation. Proven with a dummy file that
  inherited only user/SYSTEM/Administrators (`(I)` ACEs, no broad entry).
- The identity is at `%USERPROFILE%\.age\keys.txt` (env-relative; the exact profile path is not
  reproduced here). Its ACL is user + SYSTEM + Administrators only, verified by SID and by raw
  `icacls`. The public recipient is recorded in the local ops handoff, not here.
- An offline recovery copy and a restore drill are **still PENDING (owner action)**. A backup whose
  key exists on only one machine is not yet a backup.
